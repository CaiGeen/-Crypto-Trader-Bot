【1】缺陷（ChatGPT 第十三轮指出，已实证）
------------------------------------------------------------------------------
普通恢复分支解除 _poll_degraded_batches 的条件只要：
    not _poll_orders_unresolved and _poll_protection_confirmed
缺 current_actual_position is not None。于是：
  · 订单查询恢复、账本无已识别成交 → batch_filled_amount == 0
  · _poll_needs_protection = False → 保护判据被「空过」判成已确认
  · 持仓查询返回 None（UNKNOWN ≠ EMPTY）→ 旧实现照样
    「✅ [POLL] 全部批次监控恢复」并清空降级闸门 → 放行新 ENTRY
S6 首轮接管判据（trader :10752 要求 current_actual_position is not None）
只在 _monitor_lifecycle 是 dict 的接管线程生效，替不了常规监控线程。

【2】修复（隔离工作树、未提交；本文件只记录，不构成合并/部署批准）
------------------------------------------------------------------------------
恢复判定块新增第三判据：
    _poll_position_known = (current_actual_position is not None)
主 if 追加 and _poll_position_known；UNKNOWN 时不重置 streak，
并新增 elif 打印「订单已可读但持仓 UNKNOWN（查询失败 ≠ 零仓）→ 保持暂停新增风险」。
与 S6 :10752 同款 Fail-Closed。

【3】新用例 test_block35_position_unknown_keeps_degraded_gate（已注册进 main()）
------------------------------------------------------------------------------
B35a 连续失败 → 降级闸门置位
B35b 订单可读 + 持仓 UNKNOWN → 不得解除降级闸门
B35c 该状态下实际发起新 ENTRY → 必须零下单
B35d 阳性对照：持仓核实为零 → 同一条恢复路径确实放闸
B35e 阳性对照：放闸后同一替身确实落单（证 B35c 非假绿）

防假绿要点：B35c 的**信号时刻**把持仓查询恢复成 0.0，使 execute_signal
自身那道「持仓 UNKNOWN → 拒绝」(:6261) 不替本用例挡单 —— 闸门是唯一拦截。
