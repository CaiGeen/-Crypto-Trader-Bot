## 一、项目目的

对 **币安永续 BTCUSDT 4H K线** 的"6K突破 + KAMA跟踪止损 + 固定止盈"策略进行全量回测与多维度优化分析，寻找最优实盘配置。

- **语言/技术栈**：Python + pandas + numpy + ccxt，Pine Script (TradingView v6) 用于指标对照

## 二、核心策略定义

### 信号检测（`signal_detector.py`）
- **突破窗口**：前6根4H K线（不含当前根）的极值
- **做多**：`close[i] > max(high[i-6..i-1])`
- **做空**：`close[i] < min(low[i-6..i-1])`
- **突破线** = 6K区间极值（做多取max high，做空取min low）
- **信号合并**：波段区间互不重叠，落入上一波段持仓区间内的后续信号视为子信号跳过

### 入场与止损（统一口径·2026-08-22最终确认：触发线市价入场+三止损规则）
- **入场**：挂单在触发线=回调线±1×ATR（自信号K开盘生效），价格触及即市价买入（成交价=触发线）；6根K未触发作废
- **止损①**：初始止损=回调线，盘中触及按线价市价出场
- **止损②（保护性平仓）**：成交当K收盘 < 回调线±1.5×ATR → 按收盘价平仓
- **止损③（成本线时间锁）**：买入后第3K收盘未打损 → 止损上移到成本线（成交价）；此后止损=max/min(KAMA[j-1], 成本线)
- **ATR取值**：回调线当根K收盘值 `atr_vals[cb_idx]`，持仓期间固定
- 统一口径结果：**1075单 / 456.7R / 均R 0.42 / 胜率46% / 最大亏-1.00R**（出场：保护性平仓69%、KAMA跟踪16%、成本线6%、ATR止损6%、止盈3%）；成交当根路径消歧用**1分钟K线**（验证链1H→3m→1m：422.0→456.9→456.7R，3m起总量已稳定，1m为最终标准）

### 固定止盈（多空分设）
- **做多22% / 做空12%**（从突破线计算）
- 盘中达到即平仓，止损优先于止盈

### R值
- 做多：`R = (出场价 - 突破线) / ATR`
- 做空：`R = (突破线 - 出场价) / ATR`

### 技术指标
- **ATR**：RMA(tr, 20)，α=1/20，对齐TradingView
- **KAMA**：erLen=10, fast=2, slow=30（TradingView实测），`indicators.py`
- **EMA70偏离度**：日线EMA70（用日线收盘价计算），`dev = (close[i-1] - dailyEMA70) / dailyEMA70 × 100`

## 六、核心结论（详见 BACKTEST_REPORT.md）

### 最优配置演进

| 阶段 | 配置 | 累计R | 单数 | 说明 |
|------|------|-------|------|------|
| 基准 | 6K极值+KAMA+22%/12% | 993.3 | 1249 | 无过滤无加仓 |
| +加仓 | 固定2.3%含BK加仓1倍 | 1212.5 | — | +216.5R |
| 实盘真实 | 基准+加仓（开盘价出场） | 1134.1 | 1249 | 最优基础配置 |
| **回调基准** | 回调高点+0.5ATR确认+0.3ATR止损+1.5ATR加仓 | **1603.9** | 1570 | **+469.8R，全局最优** |

### 关键洞察
1. **做多22%/做空12%** 是最优止盈组合（多空分设）
2. **6K** 是最优突破窗口（均R最高6.56）
3. **低ATR环境突破质量碾压高ATR**（ATR<1.5%均R 10.96 vs >5%仅1.33）
4. **近日线EMA70的突破质量最高**（偏离度[-5%,15%)均R 8-9R）
5. **做空必须固定止盈**（KAMA回吐50.1%），做多可容忍KAMA跟踪
6. **无过滤最优**，v4联合E[R]>=0是唯一微弱有效过滤（+4.1R）
7. **trailing stop实盘优势有限**（+41.2R），基准+加仓才是最优
8. **回调基准是最有效改进**：6K内2K不创新高确认的极值点作入场基准

## 七、★最新进展：回调突破线（2026-08-22）

**脚本**：`callback_breakthrough_compare.py`

**回调突破线定义**：
- 信号仍用6K极值突破检测
- 在6K区间[i-6, i-1]中，**从左到右**扫描 j ∈ [i-6, i-3]：
  - 做多：找第一个 `highs[j+1] ≤ highs[j]` 且 `highs[j+2] ≤ highs[j]` 的 j → 回调突破线 = `highs[j]`
  - 做空：找第一个 `lows[j+1] ≥ lows[j]` 且 `lows[j+2] ≥ lows[j]` 的 j → 回调突破线 = `lows[j]`
- 找不到被2K确认的极值点 → **跳过该信号**

**对比结果**（其他逻辑完全相同：1ATR止损/第3K后KAMA保本/22%/12%止盈/信号合并）：

| 指标 | 6K极值基准 | 回调突破线 | 差异 |
|------|-----------|-----------|------|
| 单数 | 1246 | 1097 | -149 |
| **累计R** | 993.3 | **1073.5** | **+80.2** |
| 均R | 0.80 | 0.98 | +0.18 |
| 胜率 | 43% | 51% | +8pp |
| 累计收益 | 1456.2% | 1560.0% | +103.8% |

- 回调突破线比6K极值平均低0.30%（做多），入场价更低→止损更紧→R值更优
- 跳过253个无回调确认信号（多为单边急涨/急跌），胜率显著提升
- 每年都正收益，2024年提升最大（+26.6R）
- 明细：`results/回调突破线对比.csv`

### 复检（2026-08-22晚，实盘真实口径 + 波段涨跌幅核心参数 + 止损时序修正）

**复现验证**：旧版数字完全复现（1097单/1073.5R/胜率51%/回调偏移均值0.30%）✓

**口径升级**（`callback_atr_entry.py` 的 `simulate_ref`，三处变化）：
1. ATR改用**回调线当根K收盘值** `atr_vals[cb_idx]`（旧：突破K前一根）
2. 动态线（KAMA/保本）跳空穿越按**开盘价成交**（旧：一律按线价，乐观）
3. **止损时序修正（用户确认）**：前2根K用初始ATR止损，**第3根K开盘起保本/KAMA止损单已挂在场内**、按线价成交（旧：第3根收盘后才切换→出现"线挂上时价格已越过"的跳空市价亏损）。影响：1095→1136单、保本356→454、ATR止损175→111、累计R 979.9→1006.8

**归因（2×2实验）**：1073.5R → 979.9R 的 -93.6R 中，-66.2R来自跳空按开盘价、-25.6R来自ATR改回调线当根；再叠加止损时序修正+26.9R → **当前统一口径=1136单/1006.8R/均R 0.89/胜率47%/最大亏-1.00R**

**结论稳定性**：
- **波段涨跌幅箱体分布对口径变化免疫**：各次口径修正后箱体占比始终 39/42/11/7/1 附近，中位2.6%-2.8%
- 旧版"+80.2R vs 6K极值"的对照组（993.3R）来自报告旧口径；同口径A/B下回调线优势更大（+170.1R，见 `callback_breakout_ab.py`）

**新增文件**：`BAND_AMPLITUDE_REPORT.md`（★波段涨跌幅统计报告v4：统一口径=触发线市价入场+三止损；分布为左截断而非对数正态）、`band_amplitude_stats.py`（统计+5张PNG一键重跑）、`results/波段涨跌幅_极值线vs回调线_v5.csv`（1075段明细）、`callback_vs_extreme_mfe.py`（明细生成）、`export_canonical_trades.py` → `results/最优配置_统一口径_完整字段_v5.csv`（**1075行×40列逐字段自查**：触发线/保护线/成交当K收盘/出场止损线/出场前KAMA等，字段算法说明见脚本docstring）、`intrabar_1h.py`（1H消歧，60958根1H K线已缓存）；BACKTEST_REPORT.md 策略定义与2.1-2已更新为统一口径。**v4及更早CSV已过时**

## 八、★未成交单修复 + 时序验证 + 市价对比（2026-08-23）

### 8.1 未成交单修复（方案B）

**问题**：限价单挂在entry_base（回调基准），价格跳空越过entry_base时未成交。旧代码将未成交单仍模拟持仓并占用`last_exit`阻塞后续信号，但最后从统计中过滤掉——"幽灵仓位"既不算P&L又阻塞信号。

**三方案对比**（`unfilled_compare.py`）：

| 方案 | 单数 | 累计R | 均R | 胜率 | 说明 |
|------|------|-------|-----|------|------|
| A 旧逻辑 | 1328 | 1195.8 | 0.90 | 77% | 幽灵仓位阻塞信号 |
| **B 跳过** | **1465** | **1286.1** | **0.88** | **76%** | **未成交不占用last_exit** |
| C 市价追入 | 1649 | 1295.7 | 0.79 | 71% | 追入单均R仅0.20胜率34% |

**决策**：方案B。限价没买到就算了，不追不占，等下一个信号。

### 8.2 市价入场对比

**问题**：如果入场出场都改成市价（收盘价入场，不计滑点）会怎样？

**结果**（`market_vs_limit.py`）：市价入场崩溃——1778单/累计R=201.0/均R=0.11/胜率9%。原因：close[i]远高于entry_base，入场价变高→止损线抬高（前3K止损75→305单）+止盈线抬高（止盈38→18单）。**限价入场的核心优势是入场价低，止损紧止盈近。**

### 8.3 时序验证

**问题**：回调基准成立后用户直接挂单，不需要等6K突破确认。6K区间[i-6,i-1]在i-1收盘形成，i开盘挂单，6根K内成交否则作废。

**结果**（`timing_backtest.py`）：

| 成交时间 | 单数 | 累计R | 均R | 胜率 |
|----------|------|-------|-----|------|
| 信号K+0 | 1437 | 1285.3 | 0.89 | 77% |
| 信号K+1~+5 | 88 | **-35.2** | -0.40 | ~20% |

**信号K后成交的88单全部亏损**：跳空后回落到entry_base时突破动能已衰竭。**决策：信号K内撤单**（当前方案B逻辑即为正确时序）。

### 11.3 方案A过滤逻辑（事前过滤）

```
偏离度 dev = (close[i-1] - 日线EMA70) / 日线EMA70 × 100

if -2% <= dev < 6%:    入场
elif 6% <= dev < 15% and 前3K方向涨幅 < 0 and ATR% < 1.8:  入场
else:                   跳过（不占last_exit）
```

- ATR% = ATR[i-1] / close[i-1] × 100
- 前3K方向涨幅 = (close[i-1] - close[i-4]) / close[i-4] × 100（做多取原值，做空取反）

### 11.4 核心回测参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 突破窗口 | 3K | `detect_breakout(df, 3)` |
| 入场基准 | 回调基准（前3K内2K确认极值） | 找不到则用突破线 |
| 成交价 | = entry_base（限价单挂在基准线） | 不计跳空 |

### 11.6.8 量比定义修正与加仓R定义修正（generate_final_report.py）

**量比定义修正**：

之前generate_final_report.py中直接用索引取volume存在严重错位——标记价4H（14614根，2019-12-23起）和最新价4H（15249根，2019-09-08起）起点不同、长度不同，必须用`open_time_ms`做时间戳对齐。

修正后量比定义（与之前所有分档结论一致）：
```
量比 = 信号K本身volume ÷ 过去20根4H平均volume
     = vol_4h[i] / nanmean(vol_4h[i-20:i])
```
通过`searchsorted`用`open_time_ms`映射标记价索引到最新价索引，确保取到正确时间点的volume。

**加仓R定义修正**：

之前加仓R用底仓ATR做分母，概念错误。加仓是独立头寸，应该用加仓自身风险做分母。

修正后定义：
```
加仓R = (出场价 - 加仓价) / (加仓价 - 加仓时止损价)
```
- **分母**：加仓触发那根K线的止损线（`sl_at_addon`），即加仓时的初始风险
- **分子**：出场价与加仓价的差
- **保护**：当`addon_risk ≤ 0`（加仓时止损线已在加仓价上方，无风险头寸）时，加仓R=0

**为什么不用出场时止损线做分母**：止盈出场时KAMA可能已上移到加仓价上方，导致`加仓价 - 出场时止损价 ≤ 0`，产生NaN。用加仓时的止损线做分母是固定值，不会随KAMA上移而变化。

**修正后最终成绩**：

| 指标 | 修正前（底仓ATR做分母） | 修正后（加仓时止损做分母） |
|------|----------------------|--------------------------|
| 总单数 | 771 | 771 |
| 基础总R | 875.5 | 725.3 |
| E'加权总R | 1567.3 | 1285.9 |
| PF | 12.1 | 17.0 |
| 胜率 | 82% | 84% |
| 最大回撤 | -5.0R | -2.7R |

加仓R更保守后总R下降，但PF和回撤显著改善（PF 12.1→17.0，回撤-5.0→-2.7），因为加仓R的分母更大（加仓价离止损线比底仓ATR更远），单笔加仓R值更小但更真实。

**加仓R分布**：
- 161单加仓，加仓R总和54.7
- 止盈出场16单，加仓R均值3.21，贡献51.3R
- 止损出场145单，加仓R均值0.02，贡献3.3R
- addon_risk≤0保护未触发（0单）

发现61单同时触发前3K止损和3K收盘认赔。原代码只执行前3K止损（按init_stop出场），但init_stop可能远低于成本价。修复后3K收盘认赔优先于前3K止损：当第3K收盘价穿成本价时，按收盘价出场而非按init_stop出场。修复后总R略降2.2R（2504.3→2502.1），逻辑更合理。
