# 邮件通知策略变更与生产回滚手册

状态：待审阅候选；本文不构成部署授权。生产部署只可在单独批准的变更窗口执行。

## 发布范围

只发布 `email_gate.py`、`trader_260725.py`、`健康巡检.py` 三个通知模块。不要从验证候选复制 `.env`、账本、缓存、状态、日志、`sitecustomize.py`、probe 或测试驱动。测试夹具改动属于另一条 PR。

## 部署前保护

1. 获得明确的生产变更窗口、覆盖文件和启停授权；核对当前 bot/watchdog 进程、交易所持仓、活动订单、保护单、鉴权及恢复状态。若环境状态不明，停止发布。
2. 对三个目标文件分别记录 SHA-256，并复制为同目录或受控备份目录中的唯一备份；记录原路径、备份路径、哈希、时间、操作者。验证备份哈希与原文件一致后再覆盖。
3. 保存本次发布 commit、PR、部署时间、操作人和三文件新哈希。不要覆盖 `.env`、账本、订单数据或其他本地文件。
4. 在允许的验证方式下逐个替换文件；完成后校验文件哈希与批准候选相同，再按授权受控启动。

## 回滚触发与步骤

触发条件包括：Bot 无法正常启动/恢复、邮件闸门误拦明确严重事件、普通事件继续误发邮件、日报或人工 selftest 失效，或任何无法解释的通知/恢复异常。

1. 立即停止继续发布；如涉及交易安全，优先按既有运行规程安全停止新增风险并人工核对交易所实际持仓、活动订单及保护状态。不要把代码回滚当作交易所状态回滚。
2. 记录故障时间、日志和当前目标文件哈希。逐一用对应的**本次部署前备份**恢复 `email_gate.py`、`trader_260725.py`、`健康巡检.py`，恢复后逐文件核对 SHA-256 等于备份记录。
3. 只恢复上述三个文件；不回滚 `.env`、账户配置、trade state、日报状态、订单、持仓或其他生产数据，不删除新的状态文件。
4. 依授权受控启动旧版本，核验进程、鉴权、持仓、挂单及保护状态；通过 Telegram/日志核实 Bot 恢复。真实邮件收件需单独人工确认。
5. 保留故障版本备份、回滚版本哈希、命令/时间与验收结果，暂停再次部署并开复盘。

## 回滚边界与已知限制

- 文件级回滚能恢复旧程序逻辑，但不能撤回已经发出的邮件、恢复邮件提供商状态、撤销交易所订单/成交、保证旧代码兼容新状态，也不能保证在主机/磁盘/账户故障时“随时”可用。
- 因此“可回滚”是有已验证备份和可执行步骤的操作准备，不是零风险或任何故障下绝对保证。上线前必须实际校验备份可读、哈希吻合，并确保授权操作员可访问。
- 当前候选未部署；真实 SMTP 收件、交易所状态及重启恢复未被离线门禁验证。生产发布后仍需现场验收。
