# 通知治理：观测静默，真实风险保留

## 本候选边界

基线为 PR #17 发布线 `36a39ebfda8b17176128c13dbbbeedc33bf990f1`。本候选不含 PR #18 TGDIAG 接线、TG 配置导入、allowed_updates 或生产 worker overlay。不得整份覆盖生产 bot_runner.py。

本轮仅实现普通 IP 观测静默和鉴权通知定点收敛；不改变下单、保护、API 重试、鉴权识别、封锁及 probe→reconcile→unlock 恢复顺序。未部署、未重启、未改白名单、未发真实邮件或交易请求。

## 已实现

- `_record_ip_change()` 保留 IP 更新和来源日志，不发 TG/邮件、不生成 `ip_notify`。旧备用入口保持可调用但仅日志。
- 历史 `ip_notify` 队列项进入 `SILENCED`，原因 `non_actionable_ip_change`，审计 `POLICY_SILENCED`；原事件文件保留，不删除。已有静默项保持原状态。该静默仅匹配普通 IP 事件，不匹配 `auth_blocked`。
- 鉴权封锁及锁文件损坏仍产生明确风险通知。先写持久 `auth_blocked` 事件，由现有队列承担 TG 主投递；邮件独立尝试，事件类型为 `auth_blocked`。成功入队不再同时直发 TG；入队失败/返回空值时回退原 critical 直发（包含独立邮件尝试）。
- 防冲突扫描遇到已分类的 `AuthBlockedError` 仍阻断开仓，但不再把同一鉴权故障包装成第二条扫描 critical 邮件；非鉴权的扫描失败仍保留 critical 告警。
- 下单返回 None 且本地鉴权锁存在时，用户回复明确说明“鉴权封锁/盲区安全模式”，指向实际 API Key、白名单、权限及 `/auth_reset`。其余失败保留原回复，不推测具体原因。

## 投递与风险边界

主队列已有 10 秒消费周期（首次有启动等待），TG 风险通知不是零延迟直发。队列消费者不可用时，事件保留、邮件独立尝试，但邮件失败仍可能导致外部未送达；本候选不声称彻底解决所有通道同时失败。

入队是持久证据，不是 TG 送达；异步邮件返回 True 是提交线程，不是 SMTP 确认，更不是收件人阅读。队列保留原 Markdown→纯文本降级、有限重试、SILENCED 证据策略。

KNOWN_LIMITATION：投递/删事件文件之间崩溃仍可能重复，多个并发真实拒绝和跨进程巡检事件尚未统一成一个账号级故障实例。本轮不靠删除安全证据、隐藏所有 critical 或放宽 AUTH_BLOCKED 消除重复。

UPGRADE_TRIGGER：部署后若同一未恢复鉴权故障仍由并发调用/独立巡检生成重复事件，应另做持久故障标识及跨进程生命周期治理，并覆盖重启、状态损坏、风险升级和迟到投递场景。

## 后续分类规范（本轮未批量改写）

| 类型 | 目标策略 | 本轮状态 |
|---|---|---|
| 正常 IP、心跳、轮询、统计 | 日志，不打扰用户 | 普通 IP 已实现；诊断保留 |
| 用户操作回执 | TG，说明实际结果，不泛化成功 | 鉴权失败回执已明确 |
| 成交、止损/止盈、结算 | TG，一次结果尽量合并 | 原行为保留 |
| 自动维护中间步骤 | 日志；真实能力降级/持续失败才升级 | 另项，不批量降级 |
| 鉴权、保护丢失、订单 UNKNOWN、账本损坏 | 首次及时告警，后续限频，风险升级另报 | 安全告警保留；鉴权定点收敛 |
| 恢复 | 真实恢复判据通过后一次通知 | 原 probe+对账解锁/监控稳定判据保留 |
| 日报、自检 | 独立开关，明确人工自检 | 原行为保留 |

保护 UNKNOWN 不等于无单，查不到仓位不等于空仓；不能因“只接受币安拒绝”而删掉这些安全告警。所有告警持续提醒与恢复通知统一、成本待补证文案、自愈消息、重启/平仓汇总合并，应逐类单独验证，不混入本次小改动。

## 邮件独立排查

生产 `logs/bot_20261013.log` 于 09:40:37 和 09:40:58 记录 `SSL: WRONG_VERSION_NUMBER (event=critical)`；此前 `bot_20261012.log` 于 21:59:51 记录资金安全邮件成功。本次没有读取/导出邮件凭证。

三个邮件发送位置均使用 `SMTP_SSL("smtp.qq.com", 465, timeout=10)`，未发现本候选把端口改成明文 SMTP 或将本地 HTTP 代理显式传给 SMTP 的行为。SSL 错误本身无法证明 FlClash、DNS、透明代理或远端端点中的哪一处导致协议不匹配，也不能证明凭证无效。

已离线注入相同 TLS 错误，确认同步等待路径返回 False、不假报成功；邮件异常不会删除 AUTH_BLOCKED 队列事件或解除封锁。**实际 TLS 链路/SMTP 送达尚未验证，邮件故障未修复。**

后续先获准执行仅连接/握手诊断（不登录、不发信），比较 SMTP 解析目标和实际网络路径；若需要真实通道自检，再单独授权一次测试邮件。保留 SSL/TLS 验证，不关闭证书校验，不凭报错盲改为明文或自动重试发信。
